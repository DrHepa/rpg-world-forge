# Runtime compatibility, readiness, and handoff

Resolve runtime support from the requested runtime target and exact capability
requirements, never from genre, fiction, or presentation labels. Use only the
code-owned adapter registry and exact runtime snapshot/implementation,
assetpack, composition, platform-lock, and evidence identities.

Report authoring, compilation, assets, adapter, execution per platform,
packaging, and release independently. Mechanic and feature statuses are
`supported_current`, `game_extension_verified`, `authoring_only`, or `blocked`.
Platform execution is `untested`, `headless_verified`, `native_verified`, or
`failed`; local recording/fake-backend evidence is not native evidence.

`partially_supported` blocks `implementation_ready`; it does not block the
required reviewed P14 `authoring_ready` handoff. `supported` requires all
mechanics, sealed assets, a verified
adapter, exact required platform evidence, and verified packaging bound to the
same logic hash. Missing or skipped hosted evidence remains missing.

Build readiness and handoff only from validated artifacts. Materialize a game
only from a ready exact materialization bundle. The game may contain immutable
logic/assets, selected runtime code, game code, tests, and notices; it must not
contain Forge authoring data, prompts, provider SDKs, Forge dependencies, or
runtime AI.

Authoring validity is not runtime executability. A handoff is not a release
claim.
